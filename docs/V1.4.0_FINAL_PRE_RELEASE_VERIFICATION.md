## Failure diagnosis and corrections

- The first candidate workflow measured the real WinHTTP timeout at 8,016 ms against an 8,000 ms total-call harness limit. The timeout itself occurred as expected; no response-body bytes were accepted; partial/final files were removed and the previous-app sentinel was preserved. The test-only ceiling was raised to 12,000 ms while retaining a 15-second watchdog. The corrected case passed at 4,016 ms in run 44505090187. No product binary was rebuilt.
- Run 44505090187 ended overall `failure` because its `completion.json` remained `PENDING`, which blocked the dependent independent-audit and ARM64 jobs. The logs do not prove why the prior write failed. A focused helper now uses a mutable JSON hashtable, writes the missing properties, rereads the file and asserts the exact hash/cycle result. The helper passed a local PENDING-to-PASS test. The new independent workflow validates the retained raw timeout/soak evidence directly and passed both jobs in run 44527187760 without repeating the soak.
- The broad updater-acceptance run 44527196627 was canceled before its duplicate candidate build or acceptance tests began. Its outputs are not counted as test evidence.
- The broad updater-acceptance run 44533240785 was also canceled during tool setup, before candidate build, install/update tests or soak. It was an automatic duplicate triggered by the focused harness push; cancellation was deliberate so the passing candidate evidence could be reused and only targeted checks run. Post-cancel identity/gate steps reported failure because required build outputs did not exist; this was not a product test failure.
- The focused resource-loop run 44533230263 passed: eight cycles each of HTTP 503 check failure, actual fixture-download cancellation and digest rejection, plus eight recovery-helper rejection launches. The retained JSON/CSV report recorded zero sustained USER/GDI/handle slopes and an unchanged disposable profile sentinel; artifact [14535531251](https://github.com/REMEDIOSSAMUEL/EYE-BREAK-REMINDER/actions/runs/44533230263/artifacts/14535531251).
- The GUI resource fix joins completed update-check workers when results are dispatched and detaches only an in-flight worker during app destruction after invalidating dispatch. Pre-fix checks grew by one handle/check; the fixed hosted loop showed zero handle slope. No release-candidate binary was rebuilt after candidate creation.

## Remaining gates and external limits

- **Release blocker SEC-029:** app/setup signatures report `NotSigned`. The current worktree implements signed-manifest verification, but its production public key is deliberately unprovisioned; manifest authentication is separate from Windows Authenticode and must be explicitly approved as the update trust policy. Free Authenticode options reviewed: SignPath Foundation may accept an eligible OSS project, but this repository lacks a root OSI-approved license and acceptance is not guaranteed; Microsoft Store signing is free for MSIX Store distribution but does not sign the current NSIS/portable files. Certum currently charges for its Open Source certificate, and Azure Artifact Signing is paid. No certificate was obtained. See [UPDATE_SIGNING_AND_KEY_MANAGEMENT.md](UPDATE_SIGNING_AND_KEY_MANAGEMENT.md) for the exact secure key procedure and current findings. The production key, signed exact candidate, authenticated update transaction and rejection side-effect tests remain required; no test/private key is embedded in the development binary.
- Three requirements remain NOT TESTED: exhaustive rejection-side-effect mapping (`SEC-028`), origin DNS failure (`FAIL-001`), and Windows Settings > Installed Apps removal (`UN-009`). The exact candidate was exercised for refusal-to-exit, launch-denied and locked-file recovery in run 44540906174; those rows now pass.
- Eleven cases remain BLOCKED by production signing or unavailable physical/guest capabilities: native Windows 11 x64, isolated reboot/RunOnce across reboot, genuine lock/sleep-resume, multi-monitor, physical audio/Shell notifications, Narrator speech, and unavailable authorized persistent guest infrastructure. ARM64 emulation does not close native x64 coverage. The user's laptop was not used for destructive installation or power-state tests.
- PR #7 remains open/draft and unmerged. Main ruleset 27397921 must remain active. No v1.4.0 release/tag was created; published v1.3.0 and v1.2.1 remain unchanged. `REMEDIOSSAMUEL/EXERCISE-BREAK-REMINDER` was not accessed. The user's laptop was never restarted, shut down, locked, suspended or hibernated.
