## Outstanding publication gates

Publication readiness requires all of the following on the exact frozen candidate, with evidence linked here:

- Hosted native GUI, five themes, Forced Colors, accessibility names/patterns/focus, timer continuity and progress update assertions.
- Real v1.3.0 to v1.4.0 upgrade and actual in-app v1.4.1 fixture install with startup confirmation.

- Cancel, digest mismatch, interrupted-transfer retry, controlled installer failure, failed startup rollback, active-break deferral, duplicate-coordinator rejection, and interrupted-clean RunOnce recovery. Recovery will be invoked directly from its registered command in the hosted test; an actual OS reboot/automatic next-sign-in launch remains NOT TESTED.
- Portable executable replacement and relaunch without installation registration or unrelated-file removal.
- Interactive Keep/Remove uninstall, deterministic silent Keep uninstall, reinstallation, Installed Apps verification where exposed.
- 110-cycle USER/GDI/resource soak and exact candidate identity/hash recheck after runtime acceptance.
- Independent download of the retained candidate artifact and validation of all five release hashes, manifest, version, installer identity, portable contents, source snapshot, and absence of secrets/personal paths.
- Final documentation and PR/branch-protection verification.

Any not-run case must remain marked NOT TESTED. Actual power-loss/reboot recovery and unavailable machine/hardware variations must be reported with their actual limits.

## Trust and release constraints

The updater uses normal Windows TLS validation, fixed official repository/release/asset validation, allowlisted HTTPS redirects, exact expected asset names, size limits, streamed SHA-256 verification against GitHub asset metadata, and a second verification before installation. The release is unsigned; there is no signed manifest, production signing key, or Authenticode publisher signature. GitHub/TLS/digest verification does not independently authenticate the publisher if the repository account or GitHub release service is compromised. SmartScreen and Windows security warnings remain enabled.

The first v1.3.0 to v1.4.0 transition remains a normal per-user installer upgrade because v1.3.0 does not contain the integrated updater. Do not change, move, or republish v1.3.0 or v1.2.1. Keep `main` protected. Do not merge, tag, or publish v1.4.0 without the user's separate approval.
