## Security and data-preservation decision

The updater enforces HTTPS-only allowlisted GitHub destinations, release/asset/version checks, SHA-256 payload validation, size bounds, redirect rejection, constrained staging paths, safe command construction, final-boundary revalidation, a per-user update mutex, settings/history backups and rollback/recovery. The exact candidate's downloaded application and installer have matching recorded size/hash and version identity; the portable executable is byte-identical to the standalone payload. The source archive provenance matches the tested source snapshot.

**Release blocker SEC-029:** Authenticode reports `NotSigned` for the application and setup executable. SHA-256 from GitHub's release API detects corruption relative to supplied metadata but does not establish trusted publisher identity against a compromised release account or metadata source. The owner must supply a production signing identity and trusted publisher verification policy; signed-candidate acceptance and signature-rejection tests must then pass. No public test key or private key is embedded in the release files.

Security, installer, clean-install, backup, history deletion, rollback and settings recovery are exercised in disposable runner state. Production backup-failure acceptance proves destructive settings policy is not applied before a verified install begins. The user's local application data was not modified.

## Defects found and corrected

1. **Production USER/handle leak:** update checks detached a worker on every request. Retaining/joining completed workers fixed the leak; measured slope is zero in the hosted diagnostic and long soak.
2. **Timeout harness false-negative:** a real 3-second WinHTTP receive timeout plus runner overhead measured 8,016ms against an 8,000ms whole-call ceiling. The harness ceiling is now 12,000ms with a 15-second watchdog; the same actual behavior passed at 4,016ms. No product binary changed.
3. **Completion-summary evidence handoff:** run 44505090187 retained passing raw timeout/soak data but left the separate `completion.json` with `PENDING`, so downstream jobs failed before their tests. The prior cause could not be established from logs. The writer now adds fields via a JSON hashtable, rereads and asserts the persisted values; the focused write-back test passed. A separate workflow validates the raw records and passed independent audit and ARM64 without rerunning the soak.
4. **Test harness issues:** missing provenance-field assumption, PowerShell `$PID` collision, strip alias, nested GUI child lookup, and WMI OS-caption denial were corrected as harness issues. No assertions were weakened to turn an application defect into a pass.
