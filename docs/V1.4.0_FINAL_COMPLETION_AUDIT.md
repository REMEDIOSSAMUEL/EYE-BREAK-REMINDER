## Security and data-preservation decision

The updater now verifies the signed schema-1 manifest with Windows CNG ECDSA P-256/SHA-256 and revalidates metadata and payload at the transaction boundary. Production trust remains deliberately unprovisioned, so production builds reject updates until a protected public key is embedded. Disposable test roots are compiled only into EYEBREAK_TEST_BUILD. Test-key signed transactions and rejection paths pass; they do not establish production publisher authentication. Under the owner's revised policy, Authenticode is optional for v1.4.0 and the initial installer may remain unsigned with clear disclosure.

## Defects found and corrected

1. **Production USER/handle leak:** update checks detached a worker on every request. Retaining/joining completed workers fixed the leak; measured slope is zero in the hosted diagnostic and long soak.
2. **Timeout harness false-negative:** a real 3-second WinHTTP receive timeout plus runner overhead measured 8,016ms against an 8,000ms whole-call ceiling. The harness ceiling is now 12,000ms with a 15-second watchdog; the same actual behavior passed at 4,016ms. No product binary changed.
3. **Completion-summary evidence handoff:** run 44505090187 retained passing raw timeout/soak data but left the separate `completion.json` with `PENDING`, so downstream jobs failed before their tests. The prior cause could not be established from logs. The writer now adds fields via a JSON hashtable, rereads and asserts the persisted values; the focused write-back test passed. A separate workflow validates the raw records and passed independent audit and ARM64 without rerunning the soak.
4. **Focused test harness issues:** the low-space API fault injection itself passed; its separate ACL check initially used `%TEMP%` instead of the production `%LOCALAPPDATA%` parent, so the disposable root and object-ACE parsing were corrected. The failure-edge workflow initially failed before executing tests because `inputs.*` is empty on a push event; candidate-download IDs now fall back to the exact retained candidate defaults. The existing missing-provenance assumption, PowerShell `$PID` collision, strip alias, nested GUI child lookup and WMI OS-caption denial were also corrected as harness issues. No application assertion was weakened.
