## Defect history and regression prevention

A real UI defect was found: at 225% Windows text scale, the Break reminder heading clipped. It was corrected in candidate source commit b39f014 with measured wrapped caption drawing. The exact candidate passed the regression at 225%, and the heading and reminder controls remained visible.

Several earlier display-probe failures were harness defects. The probe initially failed to resolve a visible control, treated BM_CLICK transport as a success result, omitted the existing unavailable-audio dialog path, and then omitted a diagnostic field. Each was traced from the retained logs/screenshots. The final probe reused the existing acceptance helper's asynchronous manual-Break and audio-warning handling, verified the actual reminder window and its dismissal, and passed against the same sealed executable. No confirmed product defect was indicated by those failed probes.

No product or packaging source changed after the sealed candidate was built. No confirmed defect remains in the exact candidate.

The latest exact-candidate installed-only follow-up, [run 43903542427](https://github.com/REMEDIOSSAMUEL/EYE-BREAK-REMINDER/actions/runs/43903542427), did not reproduce a product failure. The tray diagnostic shows the candidate icon remained registered and the app responsive; its screenshot shows a Windows “Narrator updates” dialog covering the tray while no popup menu was present. Diagnostic evidence is retained in [artifact 14246095016](https://github.com/REMEDIOSSAMUEL/EYE-BREAK-REMINDER/actions/runs/43903542427/artifacts/14246095016). The failure is classified as Windows UI obstruction plus a harness setup gap. It is not counted as a new deduplicated coverage case and does not invalidate the successful exact-candidate tray checks in run 43857689638. A narrow Narrator-dialog cleanup and `tray-narrator-only` test mode are prepared in the verification harness; they have not yet run on Windows.

The focused follow-up cannot currently be pushed or dispatched: the available GitHub CLI token is invalid, Git Credential Manager yielded no credential without prompting, and no authenticated browser session was available. The local harness/workflow/documentation changes are not yet committed or pushed. No credentials were displayed or changed. This external authentication blocker does not change the release candidate or its prior successful evidence; it prevents completing the optional targeted rerun in this execution.

## Environment and remaining coverage

### Native Windows 11 x64

The local host is Windows 11 Pro x64, build 26300, and contains personal application data. It was inspected but not used for disruptive candidate testing. Windows Sandbox was not installed/usable; VMware vmrun, VirtualBox VBoxManage, Hyper-V Get-VM, existing disposable VMs, and authorized self-hosted runners were not available. Reading Windows optional-feature state required elevation; no feature was enabled. The repository's available hosted choices provide Windows Server x64 and Windows 11 ARM64, not native Windows 11 x64. Therefore WIN-004 is BLOCKED. ARM64 emulation does not substitute for this missing native test.

### Reboot, startup, session and display topology

Startup registration and uniqueness were checked, but no persistent disposable Windows VM was available for an actual reboot and post-login run. WIN-005 and WIN-011 are BLOCKED. Real lock/unlock and suspend/resume were not attempted on the personal host and are BLOCKED as WIN-006 and WIN-007. The hosted Windows desktop reported one display; no synthetic monitor events were treated as evidence, so WIN-008 multi-monitor/mixed-DPI coverage is BLOCKED.

### Narrator and accessibility

Accessibility names, roles, states, focus and keyboard interaction were checked. Windows Narrator was active and navigated through Timer, Appearance, custom Work/Break colors, ChooseColorW RGB/palette controls, History, Check for Updates and the Break reminder. Actual Narrator speech audio was not captured. UI Automation metadata and Narrator navigation therefore do not count as proof of speech; ACCESS-003 is NOT TESTED.

### Audio

The runner exposed no usable Windows audio endpoint for playback or WASAPI loopback. The no-output warning path was observed, but PCM generation or the warning itself is not evidence of playback. Alarm sounds, preview/stop, volume, mute, repeat, completion, snooze and pause audio output were not verified. WIN-012 is BLOCKED. Physical speaker audibility was also not tested.

### Notifications

A legacy Shell notification request was attempted while the app was hidden. Windows reported QUNS_QUIET_TIME (6) and AcceptsNotifications=false; no visible balloon appeared. The in-app Break reminder was visible. This indicates Windows quiet-time suppression, not an application failure. WIN-002 remains NOT TESTED for the visible balloon behavior. The application does not implement the modern Toast API, so WIN-003 is NOT APPLICABLE.

### Installer and standard user

The exact candidate installer, installed launch, upgrade from v1.2.1, interactive and silent uninstall, and reinstallation paths passed on Windows Server x64. A disposable non-administrator account installed to its LocalAppData path without elevation, received HKCU registration, launched the exact candidate, and completed interactive and silent uninstall. The new targeted run repeated these checks successfully.

Only Settings > Apps removal for that secondary user remains NOT TESTED. The runner's Installed apps screenshot identifies runneradmin; both Explorer URI activation and direct SystemSettings.exe activation forwarded to that interactive shell. The disposable account was removed, and no unrelated app was selected or changed. A separately logged-on standard-user desktop is needed for that specific check.

### Update-check overlap

A deterministic GUI implementation test used an injectable test-only HTTP path with start and release event barriers. It proved the response stayed unresolved while the timer advanced from 10,800 to 10,797, the UI remained responsive, the response was released, and the countdown remained correct. This test did not weaken production HTTPS. A separate live GitHub check on the exact candidate completed before the visible timer tick. Direct production-binary in-flight HTTPS overlap remains NOT TESTED in GAP-009.

### DPI and UI states

Five themes, custom Work and Break accents, distinct-break-colors disabled, High Contrast, Forced Colors, keyboard interaction and representative running/paused/Break/snoozed/scheduled states were exercised. On the exact candidate at 96 DPI, actual Windows text scale settings of 125%, 150%, 200% and 225% were checked across Timer, History, all six Settings sections, ChooseColorW, accent swatches and the Break reminder; 32, 32, 37 and 36 layout/control events passed respectively.

The full per-monitor DPI matrix could not be run because only 96 DPI and one display were available. Exhaustive hover, disabled, selected and keyboard-focus contrast measurements across every theme and extreme custom colors were not captured. ACCESS-007 and WIN-014 remain NOT TESTED. These do not negate the tested high-contrast protections and accent paths.

### Resource stability

The exact production executable completed 110 real-timer cycles over 7,558 seconds, opened 116 Break windows, performed 100 native picker operations (50 OK and 50 Cancel), and recorded 2,190 metric samples. It produced 263 PASS and 0 FAIL checks. USER objects were 164→164 (range 164–165), GDI objects 58→59 (range 57–59), and process handles 238→238 (range 237–240), with no sustained growth.
