## Coverage summary

### Application, settings, timer, and custom colours — recorded PASS

The exact production candidate passed installed-app acceptance, including fresh launch, work timer, manual and scheduled reminders, Break acknowledgement, real one-minute snooze, history recording, restart during an active Break, saved theme/custom color recovery, and no duplicate reminder or false completion. Existing recovery behavior returns an interrupted Break to fresh Work.

The native `ChooseColorW` dialog was opened in the installed candidate. Independent Work/Break RGB colors, cancel, reset, custom palette persistence, timer continuity, theme changes, and actual timer-ring pixels were checked. Extreme black/white, yellow/navy, red/pale, identical, and similar color combinations were exercised in the GUI acceptance suite. High Contrast, Forced Colors, and distinct-break-colors-disabled behavior were checked against rendered ring pixels. The candidate reset to the original Light defaults `#1D4ED8` and `#0F766E` while preserving theme, timer, schedule, startup settings, and history.

The five themes were exercised: Dark, Light, High Contrast Dark, High Contrast Light, and Follow Windows Theme. Follow Windows responded to actual Windows light/dark preference changes. Windows Forced Colors overrode accents without erasing them, preserved distinct Work/Break status text, and restored the saved colors after the OS setting was disabled.

Recorded accessibility contrast was 16.29:1 for text, 7.89:1 for primary-button text, and 11.17:1 for focus. UI Automation names and keyboard focus were inspected; keyboard Tab access to the native picker passed. DPI and 150% text scaling were exercised on the Server desktop.

The GUI suite used its accelerated test executable; its SHA was not retained and is not claimed byte-identical to the release EXE. Separate installed-picker, Forced Colors, timer-ring, active-Break restart, and 110-cycle soak evidence explicitly identifies the exact production EXE SHA above.

### Build, packaging, installer, upgrade, persistence — recorded PASS

Run 43577697331 passed `make test`, `make all`, `make package`, `make gui-test`, package verification, exact standalone/portable launch, fresh installation, interactive and silent uninstall/reinstall, and in-place upgrade from official v1.2.1. The v1.2.1 upgrade preserved nondefault theme, intervals, schedule, startup preference, alarm settings, history bytes and statistics; one startup registration remained. The installed executable matched the candidate EXE hash. A v1.1 comparison migration was also covered.

The candidate is unsigned. No code signing certificate was supplied. No v1.3.0 release or tag was created.

### Resource stability — recorded PASS

The exact production EXE completed 110 timed reminder cycles, 100 native picker operations (50 OK/50 Cancel), and 2,191 time-series samples. It created 116 Break windows. USER objects had median 164→164 (range 164–165), GDI objects 58→59 (range 57–61), and handles 238→238 (range 237–240). The soak reported no sustained USER/GDI/handle growth proportional to interaction cycles. Private bytes rose modestly; working set declined.
